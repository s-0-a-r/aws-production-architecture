# ADR-001: 3層WebシステムのアーキテクチャおよびIaC構成の選定

## ステータス
承認済み (Accepted)

## コンテキスト
AWS上で安全かつ高可用なWebシステム基盤を構築するにあたり、以下の技術的課題と制約が存在した。
1. 特定のデータセンター障害に耐えうる可用性（HA）の確保。
2. データベースパスワード等の機密情報がコードに平文混入することの防止。
3. チーム開発におけるTerraformステートファイルの競合破損防止。
4. 単一障害点（SPOF）の排除と多段防護によるセキュリティ境界の確立。

## 決定事項
1. **モジュール分割の採用**:
   単一の `main.tf` に全リソースを書く手法を排し、`vpc`、`compute_alb`、`database_rds` の3つの独立モジュールに分割した。これによりインフラの関心事を分離し、変更の影響範囲（Blast Radius）を最小限に抑えた。
2. **多段セキュリティグループ（SG連鎖）の採用**:
   WebサーバーおよびDBへの通信制御においてCIDR直接指定を避け、前段のセキュリティグループIDを参照元として指定した。これにより動的なIP変更に強いセキュリティ境界を構築した。
3. **RDS Multi-AZの採用**:
   EC2上に手動でDBクラスタを組む運用負荷を回避し、AWSマネージドのMulti-AZ構成を採用した。EBSストレージ層の同期ブロックレプリケーションとDNSフェイルオーバーにより、耐障害性を自動化した。
4. **S3 + DynamoDBによるリモートバックエンド**:
   ステートファイルをローカル管理せず、暗号化・バージョニング対応S3バケットとDynamoDB（LockID）による排他ロックテーブルを標準採用した。

## 結果とトレードオフ
- **メリット**: 高可用性とセキュリティが確保され、誰が実行しても同じ環境を安全にプロビジョニングできる再現性を獲得した。
- **受容したコスト**: 単一AZ構成と比較して、RDSインスタンスおよびEBSの維持費が約2倍となる。しかし、本番水準の可用性要件を満たすためにこのコストを正当な支出として受容した。
